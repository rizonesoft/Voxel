# Contributing to Voxel

Voxel is in its build phase: the design and the plan are fixed, and the code is being written section by section from `todo/`. The most useful contributions right now are reports and ideas, not pull requests.

## What helps most

- **A DICOM file Voxel should open and might not.** Say the modality, the manufacturer and the transfer syntax. Never attach a real patient's scan: anonymise it first, or describe it.
- **A mistake in the design or the plan.** Name the file and the line.
- **An idea.** Open an issue and say who it is for, a patient or a clinician.

## Before a pull request

No licence has been chosen yet (see `LICENSE`), so please open an issue before writing code, so we can agree how your work would be licensed.

When code changes are welcome, these rules apply:

- The interface matches `design/SPEC.md`. A change to how Voxel looks starts in `design/prototype/`, not in the app.
- Files under `design/contract/` and `design/screens/` are generated by `python scripts/render-design.py`. Do not edit them by hand.
- Work is planned in `todo/`. Run `python scripts/todo-graph.py validate` and `python scripts/todo-graph.py plan --check` before committing a change there.
- Fix a problem in the layer that owns it, with a test that fails before the fix and passes after it.
- Markdown: one line per paragraph, no em dashes or en dashes.

The full working rules are in `AGENTS.md`.

## Patient data

Never put real patient data in an issue, a pull request, a test or a screenshot. The repository's test images are synthetic phantoms labelled `PHANTOM^VOXEL`, and it stays that way.
