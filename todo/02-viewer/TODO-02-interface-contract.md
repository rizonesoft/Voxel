# TODO-02 -- Three interfaces and the design contract

> **Goal:** Voxel has three complete interfaces (Workstation, the default; Lightbox; Console) drawn from one set of controls, chosen at install or first run and changeable in Settings without a restart, and every one of the 45 designed screens matches `design/contract/` and `design/screens/` under the rules of `design/SPEC.md`, proved by a test.

> **Current state:** Measured 2026-11-17. The design is in the repository and approved by the owner: `design/SPEC.md`, `design/tokens.json`, three prototypes in `design/prototype/`, 45 pictures in `design/screens/` and 45 contract files in `design/contract/`, regenerated by `scripts/render-design.py`. No application code exists. The empty window of D00 T01 §3 is a placeholder this file replaces. The settings file comes from D02 T01 §7.

## Inputs

- `design/SPEC.md`: every section. It names the regions and sizes of each interface, the shared rules, the shortcuts, Settings, the install choice and "What 1:1 means, and how it is proved".
- `design/tokens.json`: every colour, type style, spacing step, radius and shadow §1 turns into code.
- `design/contract/<interface>/<screen>.json` and `design/screens/<interface>/<screen>.png`: what §4 compares the app against.
- `design/prototype/*.html`: the source of the icon paths (the `I` table in each page's script) and of every label and sentence.
- `docs/plans/2026-11-17-voxel-tech-stack.md`: "Decisions the owner made" (three interfaces, the install choice).
- `src/app.rs` and `src/render/gpu.rs` from D00 T01 §3, `src/settings.rs` from D02 T01 §7, `tests/common/phantom.rs` from D00 T01 §6.
- -> XREF: D02 T01 §2 -- the first controls registered through §2 and drawn by §3
- -> XREF: D05 T01 §1 -- the mode table is the registry of §2
- -> XREF: D06 T01 §6 -- the installer writes the Interface setting §7 reads

## Outcome

- `src/ui/theme.rs` holds every token of `design/tokens.json`, the three font families are embedded, and no colour or size is written anywhere else.
- `src/ui/controls.rs` lists every control once; `src/ui/panels.rs` lists every panel once; the three interfaces in `src/ui/interfaces/` only place and draw them.
- `voxel --contract <interface> <screen>` writes what the app drew, and `cargo test --test ui_contract` passes for all 45 screens.
- The Interface setting switches the interface at once and keeps the open study, and survives a restart.
- The Settings window and the first-run chooser exist and are the same in every interface.

**Adjacency:** list=not-applicable (series are found through the strip in D02 T01 §5, drawn by each interface); document=not-applicable (the interface produces nothing a user carries away); settings=applicable; reporting=not-applicable (no summaries in version 1); notifications=not-applicable (a local viewer notifies nobody); permissions=not-applicable (no access control in a local viewer); audit=not-applicable (viewing changes nothing to audit); exchange=not-applicable (import is D01 T01, export is D05 T01 §7); reverse=applicable

**Adjacency rationale:** Settings are owned here: the Interface setting (§7) with the shell as its consumer, and the Settings window (§8) as the one place every setting is changed. Reverse is "Reset to defaults" in §8, and the interface choice itself, which can always be changed back.

## 1. Theme, embedded fonts and icon set

The design is built from a fixed set of tokens. Putting them in one module, and forbidding literals elsewhere, is what makes "the colours are exactly the tokens" checkable. The fonts are embedded so the app looks the same on a PC that has none of them, and the icons are the 16 by 16 stroke paths the prototypes use.

**Phase:** 1
**Needs:** windows-host
**Surface:** no

**Build order:**

1. Write `src/ui/theme.rs` from `design/tokens.json` and embed the fonts. Done when: a test proves every token in the JSON has an equal constant.
2. Write `src/ui/icons.rs` from the prototypes' icon paths. Done when: every icon renders at 16 and 20 pixels.

- [ ] Write `src/ui/theme.rs` with one constant per entry of `color`, `space`, `radius`, `size` and `shadow` in `design/tokens.json`, and one `TextStyle` per entry of `type`. Done when: `tests/theme.rs` parses `design/tokens.json` and asserts each value equals its constant, and fails when either side changes alone. Cheaper substitute: constants typed from memory without the test must fail review.
- [ ] Add the font files for Archivo (width 88, weights 600 and 700), IBM Plex Sans (400, 600) and IBM Plex Mono (400, 500) under `assets/fonts/` with their OFL licence texts, and load them into `egui` in `src/ui/theme.rs` with `include_bytes!`. Done when: a test renders the text "0O" in the mono style offscreen and the zero is slashed, and `docs/dependencies.md` records the exe size after embedding.
- [ ] Apply the theme to `egui`'s `Style` in `src/ui/theme.rs`: widget fills, strokes, rounding, spacing, text styles and the focus ring of `design/SPEC.md` ("States the pictures do not show"). Done when: a test reads the applied `Style` and asserts the inactive, hovered, active and disabled widget colours are the tokens.
- [ ] Write `src/ui/icons.rs`: one function per icon of the `I` table in `design/prototype/workstation.html` (and `console.html` for any it lacks), drawing the path with `egui`'s painter at a given size and colour with a 1.6 stroke at 16 pixels. Done when: `tests/icons.rs` renders each icon offscreen and asserts it has painted pixels inside its box and none outside.
- [ ] Add a test in `tests/theme.rs` that scans `src/ui/` for colour literals (`Color32::from_rgb`, hex strings) outside `theme.rs`. Done when: the test passes on the tree and fails when a literal is added to another file. Cheaper substitute: a comment asking authors not to add literals must fail; the test enforces it.
- [ ] Commit: `ui: theme from the design tokens, fonts and icons`

**Test checkpoint:** `cargo test --test theme` and `cargo test --test icons` pass; changing `signal` in `design/tokens.json` without changing `src/ui/theme.rs` fails the token test.

## 2. Control and panel registry

Three interfaces must offer exactly the same functions. The registry makes that structural: a control (its label, shortcut, icon, modes and action) and a panel (its content) are defined once, and an interface can only place them. A feature added later appears in all three or in none.

**Phase:** 1
**Needs:** windows-host
**Surface:** no

**Build order:**

1. Write `src/ui/controls.rs` with the control table and `src/ui/panels.rs` with the panel table. Done when: unit tests cover lookup, modes and shortcuts.
2. Route keyboard shortcuts through the table. Done when: a shortcut test passes for an enabled and a hidden control.

- [ ] Define `ControlId`, `Control` (label, shortcut, icon, tooltip, the modes it appears in, a group) and `ControlState` (enabled, active, the reason when disabled) in `src/ui/controls.rs`, with one entry per control named in `design/SPEC.md` ("What all three interfaces share" and "Shortcuts"). Done when: a unit test asserts the plain-mode set and the clinician-mode set equal the lists in the SPEC.
- [ ] Define `PanelId` and the `Panel` trait in `src/ui/panels.rs` (a title, a `micro` code, and a function that draws the content into a given `egui::Ui`), with the ids Window, Measurements, Layout, Rendering3d, Planes, Tags, Export and Only2d from the Console inspector table of `design/SPEC.md`. Done when: `cargo build` exits 0 and a unit test lists the eight ids.
- [ ] Write `Controls::dispatch(id, app)` in `src/ui/controls.rs` as the one place an action runs, used by clicks and by shortcuts. Done when: a unit test triggers a test control by click and by key and counts two calls of the same function. Cheaper substitute: an interface calling an action directly must fail review; a test asserts no file under `src/ui/interfaces/` names an action function.
- [ ] Route key presses through the table in `src/ui/controls.rs`, ignoring the shortcut of a control hidden in the current mode or disabled, and ignoring all shortcuts while a text field has focus. Done when: unit tests cover an enabled control, a hidden one, a disabled one and a focused text field.
- [ ] Define the `Interface` trait in `src/ui/interfaces/mod.rs`: `draw(&mut self, ctx, app)` with access to the control table, the panel table, the series list and the image area, and nothing that changes the study. Done when: `cargo build` exits 0 with a test interface that draws every control as a plain button.
- [ ] Add `tests/registry.rs` asserting every `ControlId` has a label, a tooltip that ends with its shortcut in brackets when it has one, and an icon, and that no two controls share a shortcut. Done when: the test passes and fails when a duplicate shortcut is added.
- [ ] Commit: `ui: control and panel registry`

**Test checkpoint:** `cargo test controls` and `cargo test --test registry` pass; giving two controls the same shortcut fails the registry test.

## 4. Contract mode and the contract test

"1:1" needs a judge that is not a person's eye. The app can describe what it drew in the same shape as the contract files, and a test compares the two under the tolerances of `design/SPEC.md`. From here on, every interface section is checked by it.

**Phase:** 1
**Needs:** windows-host, display-session
**Surface:** no

**Build order:**

1. Add `--contract <interface> <screen>` to the app, writing the JSON and a screenshot. Done when: it writes both for the Workstation `empty` screen.
2. Write `tests/ui_contract.rs` with the comparison rules and a report. Done when: it passes for a screen that matches and names each difference for one that does not.

- [ ] Record every control and every text the app draws in a per-frame list in `src/ui/contract.rs` (kind, label, shortcut, tooltip, enabled, value, options, rectangle, fill, ink, radius; text, rectangle, font, size, weight, ink), in the shape of `design/contract/workstation/stack.json`. Done when: a unit test draws one button and one label and reads both back from the list.
- [ ] Add `--contract <interface> <screen> --out <dir>` in `src/main.rs`: load the phantom fixture for that screen, open a 1440 by 900 window with a scale of 1, draw until the frame is stable, write `<screen>.json` and `<screen>.png` to the folder, and exit 0. Done when: `voxel --contract workstation empty --out <dir>` writes both files, and an unknown screen exits 2 with the list of screens.
- [ ] Write the fixture for each of the 15 screens in `src/ui/contract.rs`, built on `tests/common/phantom.rs` moved to `src/fixtures.rs` behind the `contract` cargo feature: the patient "Phantom, Voxel", the five MR Brain series and the chest X-ray of `design/SPEC.md`. Done when: the feature is off in release builds (`cargo tree -e features` shows it only for tests) and each screen name loads its fixture.
- [ ] Write the comparison in `tests/ui_contract.rs` with the rules of `design/SPEC.md` ("What 1:1 means"): controls matched by label with none missing or extra; label, shortcut, tooltip, state, options and value equal; control edges within 2 pixels; texts present with equal font, size and weight; text left and top within 3 pixels; colours equal. Done when: a unit test of the comparison passes for equal inputs and reports one named difference per rule for inputs that break each rule.
- [ ] Add the picture rule to `tests/ui_contract.rs`: outside the image panes, after a 1 pixel blur, no more than 2 percent of pixels differ from `design/screens/<interface>/<screen>.png`. Done when: the rule passes for the reference against itself and fails against a copy with a 40 pixel bar painted over it.
- [ ] Print a report per screen in `tests/ui_contract.rs`: each missing, extra or differing control and text with the contract's value and the app's. Done when: `cargo test --test ui_contract` passes with the `workstation/empty` screen compared and the pending count printed. Cheaper substitute: deleting a screen from the list must fail; a test asserts built plus pending equals 45.
- [ ] Commit: `ui: contract mode and the contract test`

**Test checkpoint:** `cargo test --test ui_contract` passes and prints the pending count; moving the Workstation toolbar down by 5 pixels fails `workstation/empty` with the controls named.
